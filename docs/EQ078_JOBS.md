# EQ078 optional native asynchronous jobs — development candidate

[Story88](https://github.com/atulsrivas1/equity-features/issues/88) is In progress. This is optional service0.1.0a1 candidate behavior; no released async endpoint or final qualification is claimed. [Approved decisions](EQ078_DECISIONS.md) and [frozen native fixtures](EQ078_NATIVE_FEASIBILITY.json) pin owned registrations. Transport1.0/1.1 schemas and accepted calculations/worker/I/O bytes remain unchanged. Old EQ0770.1.0a0 acceptance remains historical and valid for that package.

## Trusted startup API

Install the optional service jobs extra with the pinned equity-feature-workers0.1.0a13 dependency. Base service import does not import workers or require DuckDB. Import JobRegistration, JobGrant and JobScheduler explicitly from equity_feature_service.jobs. Provision the existing Ledger with opaque Credential values, current dataset rights and explicit calculate/job_manage/retain actions; prior slice grants gain no rights. One JobScheduler attaches to one Ledger and is reused by all Service(ledger,jobs=scheduler) controllers; a second scheduler on that ledger is rejected. Service(ledger) preserves existing slice/discovery behavior.

JobRegistration(request,spec,delivery,sources=...,source=...,sinks=...,sink_id=...,sink_config=...,credentials=...) is trusted operator setup, never caller deserialization. request is the exact closed calculate envelope, spec is an exact bounded SessionCommandSpec, and delivery is the full original admitted AdapterBatch. Initial supported registrations are trades/bars/trade_snapshot quotes; history/RequiredCommandSpec is not advertised. Pin source and sink registrations/configs and exact original acquisition scope/request/receipt/content. The selected request pairs must match the immutable registration, while JobGrant(grant_id,config_digest,features) authorizes the complete native executed family inventory. The service uses native public acquisition planning and exact-plan approval on the execution thread; source/sink factories and publication remain owned by that thread.

## HTTP and actual states

Closed calculate requests to the existing POST /v1/request return an opaque job envelope. HTTP request_id is correlation only; idempotency_key is scoped to principal and full command/grant/policy/registration identity. Identical admitted retries return the same job, including failed/cancelled/expired records, with no duplicate execution. A changed command conflicts or denies before I/O. Foreign/unknown job_status/job_cancel both return the same fixed authorization denial. Current token and pinned grant rights are checked at admission, execution boundaries and first visible HTTP chunk. Discovery only advertises authorized registered pairs.

Snapshots are actual queued/running/succeeded/failed/cancel_requested/cancelled/expired states, without invented percentages. Only native verified commit/readback and final authorization yield succeeded and an opaque result ID. EQ078 does not expose result download; EQ079 owns that qualification. Cancellation of queued work releases output reservation once without source calls. Running cancellation/deadline remains charged until actual native exit. Native commit followed by cancellation/readback failure preserves the exact captured historical receipt internally with no visible result ID and no retry execution. After verified success, cancellation is idempotent. Revocation can deny historical result visibility without asserting rollback. Cleanup remains creating-thread owned after revocation.

## Fixed bounds and limits

One shared actual running job, one queued per principal and two queued globally;16 records globally/eight per principal;8192 bytes of canonical metadata per record. Reserve262144 retained-output bytes before native work within the existing1MiB principal/2MiB global retained bounds. Count complete encoded native result (65536), original producer wire result (131072), combined envelope/receipt (32768) and their aggregate. Explicit source max100 rows/one batch/1MiB input and complete full-binding verification remain required. Job grants are half-open and valid at most3600seconds. Payloads expire at min(actual completion+300seconds, original grant expiry); terminal tombstones persist until that grant expires and are not evicted to admit more work. Background sweeps and admission/status cleanup remove encoded payloads physically. Thirty-second monotonic deadline is cooperative, not CPU/RSS preemption. close(timeout=...) stops admission, cancels owned work and reports whether the actual worker thread joined; it cannot claim exit while native work continues.

State is in memory. A restart creates a new job epoch and cannot recover prior jobs/receipts or guarantee cross-restart retry idempotency. Clients must not retry old commands across epochs; client/hosted recovery qualification is pending EQ083/084. No production resilience, hard memory/process isolation, hosted entitlement, public endpoint or stable/registry release is claimed. Use owned synthetic qualification only.
