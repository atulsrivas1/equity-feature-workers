## Capacity is an ordinary pending-queue predicate

[ioq.c](https://github.com/winfsp/winfsp/blob/ddca7bd5481857a65ba552f643b8776fd070836f/src/sys/ioq.c) rejects ordinary pending insertion when PendingIrpCount reaches PendingIrpCapacity. A nonzero insert context bypasses that predicate; BestEffort posts use this path and an infinity timestamp. Processing and retried insert paths have separate counts with no corresponding capacity check in those functions. The already pinned driver.h defines FSP_IOQ_PROCESS_NO_CANCEL, affecting infinite processing/retry timestamps and the timeout sweep. These facts do not prove actual uncontrolled growth: they establish that IrpCapacity is not itself a global bound on every outstanding request or its buffers. Whole admission, transfer, reserved cleanup and final cancellation lifetimes need a separate supported proof. Never multiply IrpCapacity by one buffer size and declare all kernel memory bounded.
