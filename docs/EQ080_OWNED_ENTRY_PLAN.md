# EQ080 frozen owned entry inventory refinement — before implementation

[Story90](https://github.com/atulsrivas1/equity-features/issues/90) remains In progress. This concretizes the acknowledged owned inventory/startup-before-handshake gate in the published EQ080 plan, without changing OS resource limits, rights, calculations, transport schemas or hosted scope. New source implementation follows separate planning disposition. The current lower-level trusted run(Path,args) is development qualification only and cannot advertise the final owned service profile.

Register an immutable server-owned synthetic entry profile before launch: a fixed ASCII profile ID (1..64 chars), exact UTF8 Python source at most8192bytes, SHA256 of those original bytes, fixed trusted argument tuple whose complete canonical encoding fits4096bytes, and explicit owned_synthetic=True attestation. Provision at most four distinct profiles in one immutable inventory. No HTTP input may create an entry, supply source/path/arguments, choose the inventory or alter registration. The inventory is an operator composition boundary, not hosted dataset rights or a hostile-code sandbox. The concrete admitted qualification inventory consists only of owned Service/native fixture programs with mandatory OwnedAudit, three frozen synthetic families and known read/compute/publish registrations; fault variants remain explicit trusted qualification entries.

Snapshot entry source bytes at admission; verify supplied SHA and bounded UTF8/code compilation before child launch. Child executes that same frozen snapshot after physical guard establishment and installation admission; no mutable entry-file read at execution and no TOCTOU source replacement. Existing developer run(Path,args) remains available only on an unregistered supervisor; a registered supervisor rejects that bypass. Run an admitted fixed profile without per-call source/path/arguments. Fixed inventory entries and exact snapshots are server configuration; not an HTTP code execution surface.

Bootstrap keeps actual base interpreter-I/-S, Linux original-parent/limits/no-new-privileges/seccomp before installation/site/native imports, and Windows atomic queried job membership before resume. After guards and frozen-source integrity verification, child writes one canonical startup frame to a dedicated startup pipe and closes its write end before waiting for ACK on its dedicated stdin pipe. The parent closes its own copy of the child startup-write end immediately after spawn, reads startup through observed EOF with an inclusive512byte limit, and validates the complete single frame, parent-created opaque epoch/challenge, admitted profile ID and source SHA. Extra bytes, duplicate records, malformed/missing frame or failure to observe EOF deny admission before ACK. Child cannot reach installation/site/Service/native imports, factories, loopback startup or request handling until the exact bounded ACK; exit status cannot substitute for admission.

The continuing combined stdout/stderr stream is separate bounded diagnostics. Startup-looking output after admission is a post-admission protocol fault that may terminate an already admitted epoch; it cannot promise prevention of earlier factory work or rollback of native publication. The pre-start guarantee applies to the closed pre-ACK startup frame, not arbitrary future diagnostics. Startup bytes and diagnostics share the existing inclusive65536 aggregate output budget; there is no extra uncharged startup allowance. Startup frame maximum512bytes and ACK maximum65ASCIIbytes contain no caller text or general request stream.

Only child stdin-read, startup-write and combined stdout/stderr-write handles inherit; parent ACK-write/startup-read/capture-read and job/control handles do not inherit. On Windows use the explicit inherited handle list with atomic suspended job admission. On Linux use close_fds plus only the startup write descriptor in pass_fds, with parent endpoints noninheritable. Track each handle/CRT descriptor/stream and successfully started reader separately through every setup failure. Missing/closed/wrong ACK, invalid startup or parent death closes admission, triggers termination, and holds shared capacity until actual exit and all startup/ACK/capture pipes and readers are closed. The existing monotonic whole-epoch deadline includes guard and handshake waits; no automatic restart/reexecution.

Bound complete encoded launch metadata to16384bytes and enforce the supported Windows command-line ceiling before launch. Frozen admitted source bytes are supplied as bounded encoded metadata and verified before startup, rather than reread from a mutable path. Installation admission and owned program execution occur only after physical guards, closed-frame validation and exact ACK. This IPC is a trusted operator qualification boundary, not dataset permission or a hostile-code sandbox.

Independent decisions/tests: four-entry inclusive/fifth/duplicate/profiletype and8192/8193 source/4096 argument/16384 metadata bounds; wrong SHA/invalid UTF8/code compilation/unsupported host deny before native factory; registered legacy bypass denies; file mutation after registration executes original frozen program; original parent death before admitted startup prevents native factory/visible endpoint; wrong/missing/duplicate or513byte startup frames and absent EOF fail before ACK; exactly512byte frame boundary, delayed post-ACK startup-shaped diagnostics have only post-admission failure semantics; closed/wrong ACK and reader-start/descriptor-wrapper failures release resources only after observed exit; real mandatory OwnedAudit/native three-family entry is guarded before startup marker; actual native CPU/memory/process/wall callbacks and committed-receipt witness; capacity until observed exit/captureclosed; new epoch does not resurrect old cache/audit/job IDs. The witness is a returned accepted ExampleSink native receipt copied to an explicitly owned external file after actual commit. Its in-memory artifact dies with the epoch: no durable native payload/Parquet/recovery/rollback claim. Extra backend installed qualification remains separately documented.

This is candidate design to review before source changes. Production hosted entry, TLS, identities, non-owned datasets/registries/recovery/backup/operations remain EQ084-gated. No new operational authorization is requested or implied.
