# EQ080 frozen owned entry inventory refinement — before implementation

[Story90](https://github.com/atulsrivas1/equity-features/issues/90) remains In progress. This concretizes the acknowledged owned inventory/startup-before-handshake gate in the published EQ080 plan, without changing OS resource limits, rights, calculations, transport schemas or hosted scope. New source implementation follows separate planning disposition. The current lower-level trusted run(Path,args) is development qualification only and cannot advertise the final owned service profile.

Register an immutable server-owned synthetic entry profile before launch: a fixed ASCII profile ID (1..64 chars), exact UTF8 Python source at most8192bytes, SHA256 of those original bytes, fixed trusted argument tuple whose complete canonical encoding fits4096bytes, and explicit owned_synthetic=True attestation. Provision at most four distinct profiles in one immutable inventory. No HTTP input may create an entry, supply source/path/arguments, choose the inventory or alter registration. The inventory is an operator composition boundary, not hosted dataset rights or a hostile-code sandbox. The concrete admitted qualification inventory consists only of owned Service/native fixture programs with mandatory OwnedAudit, three frozen synthetic families and known read/compute/publish registrations; fault variants remain explicit trusted qualification entries.

Snapshot entry source bytes at admission; verify supplied SHA and bounded UTF8/code compilation before child launch. Child executes that same frozen snapshot after physical guard establishment and installation admission; no mutable entry-file read at execution and no TOCTOU source replacement. Existing developer run(Path,args) remains available only on an unregistered supervisor; a registered supervisor rejects that bypass. Run an admitted fixed profile without per-call source/path/arguments. Fixed inventory entries and exact snapshots are server configuration; not an HTTP code execution surface.

Bootstrap keeps actual base interpreter-I/-S, Linux original-parent/limits/no-new-privileges/seccomp before installation/site/native imports, and Windows atomic queried job membership before resume. After guards and frozen-source integrity verification and before installation/site/native imports, emit one bounded fixed-format startup record tied to the parent-created opaque epoch, admitted profile ID and source SHA, before owned Service/factory/loopback startup or request handling. Parent validates the first record shape/identity/source SHA and parent-created challenge before sending one bounded fixed ACK over a dedicated inherited stdin pipe. Child blocks before installation/site/Service/native imports and owned program execution until the exact ACK; it cannot substitute exit status for admission. Only the required child stdin-read and combined stdout-stderr handles inherit; no job/control/ACK-write handle inheritance. Startup failure, malformed/missing/duplicate record or wrong/absent ACK prevents factory/endpoint/request handling, triggers parent termination and never advertises admission. Startup record maximum512bytes; ACK maximum65ASCIIbytes, no caller text or general request stream. Parent deadline covers guard/handshake wait and all later work, with capacity held through observed exit/capture and pipe closure. Bound complete launch metadata to16384 encoded bytes and enforce supported Windows command-line ceiling before launch. Existing combined stdout/stderr65536 cap includes startup record; startup capture cannot bypass output/capacity bounds. Output after the record remains bounded trusted diagnostics, not an HTTP payload or audit bypass. No automatic restart/reexecution.

Independent decisions/tests: four-entry inclusive/fifth/duplicate/profiletype and8192/8193 source/4096 argument/16384 metadata bounds; wrong SHA/invalid UTF8/code compilation/unsupported host deny before native factory; registered legacy bypass denies; file mutation after registration executes original frozen program; original parent death before admitted startup prevents native factory/visible endpoint; wrong/missing/duplicate startup records fail admission; real mandatory OwnedAudit/native three-family entry is guarded before startup marker; actual native CPU/memory/process/wall callbacks and committed-receipt witness; capacity until observed exit/captureclosed; new epoch does not resurrect old cache/audit/job IDs. The witness is a returned accepted ExampleSink native receipt copied to an explicitly owned external file after actual commit. Its in-memory artifact dies with the epoch: no durable native payload/Parquet/recovery/rollback claim. Extra backend installed qualification remains separately documented.

This is candidate design to review before source changes. Production hosted entry, TLS, identities, non-owned datasets/registries/recovery/backup/operations remain EQ084-gated. No new operational authorization is requested or implied.
