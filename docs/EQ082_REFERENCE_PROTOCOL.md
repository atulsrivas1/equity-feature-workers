## Proposed protocol and numerical profile for concrete review

Product runtime depends on accepted public equity-feature-client plus a separately pinned schema validator, not MCP SDK or a model library. Proposed runner is synchronous in the owning thread, one active call and no worker/background threads or pre-read input queue. Read binary stdin at most16385bytes to decide a16384byte frame INCLUDING one LF; reject overflow, absent LF at EOF, invalid UTF8, duplicate keys, nonfinite JSON, depth above32 or more than10000 nodes. Do not use unbounded readline. JSON-RPC batch arrays are unsupported. Output is one encoded LF-terminated frame at most65536bytes INCLUDING LF, staged and measured before any write; complete structured output is at most16384 canonical JSON bytes and the matching text block doubles its representation, so the actual entire encoded frame still needs measurement. Argument object cap4096 canonical bytes, accepted backend response cap262144 remains unchanged. No general process-memory/RSS claim follows from these bounds.

Proposed IDs are exact nonboolean integers0..2147483647 or ASCII strings1..64; no float/null request IDs. No retained completed-ID history or global ID-uniqueness claim. Malformed request errors may use null response ID, while well-formed request IDs echo exactly. initialize is once, followed by notifications/initialized before tools/list or tools/call; ping returns an empty object. Only tools capability with listChanged:false; no resources/prompts/sampling/tasks/progress/logging/pagination support. Unknown requests get fixed -32601, malformed JSON -32700, malformed request -32600, invalid method parameters -32602, internal failure -32603. Error messages are fixed inert codes, never caller/provider/server text. Legitimate tool execution failures use CallToolResult isError:true, not arbitrary JSON-RPC errors. Output overflow returns a fixed bounded tool failure before bytes become visible.

Version negotiation follows the pinned lifecycle: respond2025-11-25 even to a different well-formed proposed revision; an unsupported client should disconnect. This is not advertising that other versions work. Extra negotiated client capabilities are not server capabilities. Exact allowed initialize metadata fields and limits, input/output schemas and unknown-notification handling remain to be frozen against actual SDK frames, rather than rejecting the SDK's valid default initialization by assumption.

Protocol cancellation is optional. The versioned specification permits ignoring an unknown/completed/uncancellable request. In this proposed synchronous profile, cancellation and EOF cannot interrupt an active synchronous token provider, DNS or transport call; they are observed only after it returns. No hidden reader thread or automatic RemoteClient replacement/replay is introduced. notifications/cancelled is consumed without logging its reason or issuing backend job_cancel. Explicit job_cancel remains a separate mutation tool. Client.close permanently closes that client; runner shutdown closes it once. EOF observed between calls closes cleanly; broken output exits without emitting a partial success. Trusted owner callbacks must be bounded in actual qualification, and the owner/reference launcher may terminate a stuck process; no hard graceful-exit guarantee for arbitrary callbacks or rollback of a possibly sent mutation. Cancellation/EOF/partial-output/native-service real-exit adversaries remain mandatory before Ready and final acceptance.
