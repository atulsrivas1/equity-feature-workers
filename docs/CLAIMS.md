# Experimental local claims - worker0.1.0a8

EQ063#71. [Frozen pre-code contract](CLAIMS_PLAN.md) is authority for limits, timing and independent oracle. ClaimLimits(max_tasks=64,max_total_bytes=8388608,max_record_bytes=1048576,max_attempts=3) bounds active operational records and started calculations. Interrupted temporary bytes and native/interpreter RSS remain outside these logical limits. Task and all result/publication schemas unchanged; no mandatory dependency change.

ClaimStore(root,limits=...,requirements=...,protected_sources=()) is caller-owned creating-thread local Windows/Linux storage under .efworker-claims1, separate from source/output/catalog. Constructor performs no writes. Caller supplies sealed observed TaskManifest; no pre-acquisition deduplication/source authentication. acquire(task,owner_id=...,attempt_id=...,issued_at_ns=...,expires_at_ns=...,now_ns=...,clear_cancel=False) returns a creating-thread TaskClaim context manager retaining a stable per-task OS lock. Supplied int64 UTC nanoseconds admit issued<=now<expires. Expiry stops a new run step; it cannot steal a live publisher's lock. close is idempotent; foreign thread, closed handle and reentry reject. Crash/exit releases ownership; lock files are never removed/replaced. request_cancel(task) stores a cooperative flag under the shared metadata lock; another caller/thread uses its own store instance. Explicit clear_cancel on acquisition resumes cancelled work.

handle.run(calculate,sink,now_ns=...,cancellation=None) makes one bounded pass and returns ClaimProgress(identity,attempts,output,results,reason). calculate is caller-trusted supplied code returning tuple[FeatureResult,...], with no persisted executable/pickle or automatic fetching/scheduler. It can invoke existing prepared session/history computation with supplied inputs. Sink capability admission precedes calculation. Results use SDK preparation/entity/byte admission; standard computed results are retained on publication faults. Completion output appears only after actual receipt/result readback, not from a local state flag. Terminal waiting reasons can be sink, barrier/command or RETRY_EXHAUSTED fixed codes, without caller text.

Before any sink begin, persist an exact existing OutputManifest intent. A resumed owner always checks actual SDK lookup, receipt and full logical readback first, even when cancelled or retries are exhausted. Committed work returns original results/receipt with zero callback/new begin. UNKNOWN/STAGING/readback fault waits; only ABSENT/ABORTED permits recalculation and the result envelope must equal prior intent. Attempts count callbacks started, not ownership acquisitions or readback. Cancellation before callback or before publication prevents it; after actual commit, retained intent allows the next readback to recognize completion. No exactly-once execution, catalog acceptance, hard callback preemption, live-lock takeover, network filesystem or power-loss promise.

The root is caller-trusted private metadata; reject unknown files, symlinks, oversized/corrupt target records and declared source overlap in either direction. Updates use exclusive temporary write/flush/fsync/replace, retain interrupted files and never recursively clean caller data. Stable writer lock serializes task-count/aggregate record admission and cancellation; task ownership remains held through sink operations, while writer lock does not. Existing sink locks still serialize Parquet per output root and DuckDB per database.

Runnable installed synthetic example: python tests/claims_example.py. Actual source/native/installed/review/release evidence is recorded in EQ063_DELIVERY.md when available; implementation alone does not qualify release. EQ064 catalog,065 structured diagnostics and066 physical/pilot stay separate.
