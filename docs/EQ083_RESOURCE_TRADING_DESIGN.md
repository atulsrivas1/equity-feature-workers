# EQ083 resource-trading subsystem candidate

PRIMARY DOCUMENTATION RESEARCH AND PROPOSED DESIGN ONLY. This chooses a more specific feasibility direction: one parent-owned guest and provider subsystem with physical RAM/capability budgets, kernel-memory policy, session-specific backing and documented Windows/Linux virtualization. It does not select a supported complete runtime topology, dependency release, kernel, hardware, guest image, ABI, license or issuer. No source implementation or operational action is authorized by this design. Existing source/runtime/API/math/tests/workflows unchanged; newtests0.

## Documented mechanisms and version boundaries

[Genode Foundations25.05 resource trading](https://genode.org/documentation/genode-foundations/25.05/architecture/Resource_trading.html) documents PD physical-memory balances, reference-account transfers and session donations. Actual per-session backing stores are needed; counters over a shared heap do not guarantee return of physical backing. A server may fail to release donated memory and a quota withdrawal may fail. Resource requests and yield responses are policy/cooperation, not hard completed reclamation. Disk-space policy belongs to higher-level servers. These contracts are narrower than a whole-machine cap or cleanup deadline.

The [core description](https://genode.org/documentation/genode-foundations/25.05/architecture/Core_-_the_root_of_the_component_tree.html) includes quota-bounded RAM and capability allocators, page-granular dataspaces, PD-close reclamation and separate IO_MEM/IO_PORT/IRQ authority. Dataspaces can be shared; mappings, device buffers and raw-device authority remain separate considerations. No actual closure or physical release was observed.

[Recursive ownership](https://genode.org/documentation/genode-foundations/25.05/architecture/Recursive_system_structure.html) gives parents creation/destruction and session-routing authority. It also warns that synchronous RPC to a nonresponding server can block indefinitely. Parent authority to destroy a server is not itself a bound on the caller's complete teardown. The owner must not delegate its failure path to an unbounded server call.

[Release15.08](https://genode.org/documentation/release-notes/15.08) is historical evidence for NOVA kernel-memory accounting per protection domain and quota-depletion handling. Its described OOM policy tries quota upgrades, then mapping revocation, then thread stop. This is not a frozen nonexpanding budget. Do not silently assume that historical heuristic remains unchanged, has been removed, or is a selected current configuration.

[Release21.02](https://genode.org/documentation/release-notes/21.02) describes a VirtualBox6 development snapshot running Windows and Linux guests. [Release25.05](https://genode.org/documentation/release-notes/25.05) removes VirtualBox5. The current [26.08 release](https://genode.org/documentation/release-notes/26.08) explicitly supports the VirtualBox7.2.14 port and describes Linux and Windows11 boot, UEFI, TPM2 and Secure Boot. It identifies the old6.1 port as end of life. These are actual port support statements, stronger than inferring compatibility from upstream VirtualBox alone. They are not proof of our exact x64 CPython3.12.10 native wheels, selected OS images, features, installed forms, source-to-binary closure or resource behavior. The same release adds VFS reconfiguration; future policy must control any such mutation explicitly. No port or image was acquired or run.

## Proposed ONE-subsystem topology and all-domain admission contract

This table is a project design inference, not a description of an already supported configuration. It is one candidate graph to substantiate, not separately deployable wrappers. No positive admission is permitted while any row lacks actual supported enforcement.

| Owner or component | Fixed authority and reservation to substantiate |
| --- | --- |
| Initial root/controller | Entire kernel/core/init/bootstrap/source ROM and controller overhead identified and included before child construction. Fixed parent PD RAM/capability budget plus every relevant kernel-memory budget. No automatic quota enlargement from outside the selected total; no unowned root/session transfer. Initial raw source/root/interpreter/stdlib/native verification before imports/callbacks in all actual owners. |
| One VMM and one guest execution epoch | VMM/device models, guest RAM, page/EPT mappings, threads, IPC and temporary overlap all within explicitly charged owners. Exact supported x64 Windows or Linux image and native-artifact mode; no guest-controlled device additions, resource upgrades or physical passthrough. An epoch is not reusable until physical obligations settle. |
| Dedicated writable backing provider | A separately owned provider inside the same subsystem; all scratch/profile/temp/registry/pagefile/log and every guest writable location denied or backed by the selected complete quota domain. Bytes, nodes, pending/deleted-open/replaced objects, contexts, request and teardown debt bounded before acceptance. RAM quota alone does not establish required file/node semantics or cumulative-write policy. |
| Dedicated transfer/ROM/result services | Every session has independent backing and retained reservation through actual return. Exact immutable input objects and bounded output buffers only. Broker/controller/session construction overhead charged before allocation. No shared outside server, unconstrained log sink, network, USB, host-share or device allocation path admitted merely because guest RAM is limited. |
| Independent failure controller | Reserved cleanup resources and execution authority remain usable after guest/provider failure. Stop new mutations, terminate all owned execution, settle queued service work and device writers, destroy actual sessions/PDs and reconcile donated backing/kernel charges; no synchronous unbounded RPC in the failure path. No watchdog-to-completed-free substitution. |

The candidate needs a source-backed conservation proof over the entire graph. Transfers change which account owns a charge, not the frozen total. Bootstrap/core overhead and kernel-object charges cannot be hidden outside the total. The proof must close every quota-upgrade/OOM/reconfiguration/mapping/capability delegation path and every partial constructor/failure branch. It must establish independent backing, not count an object free while its shared dataspace remains allocated. No numeric limits or current configuration are invented here.

Destruction needs a separately supported finite contract for each owned component, server queue, kernel object and device writer. A failed withdrawal, stuck RPC, unknown mapping or unresolved finalizer retains its original charge and root/provider authority and denies the epoch. Destroying a visible child or observing an empty account cannot attest external DMA or unowned storage release. Reset, reboot, parent process exit and reported free space are not cleanup witnesses. Actual nofollow residual cleanup must finish or be explicitly recorded failed before final owned closes; borrowed roots never close and void cleanup inconsistency poisons.

The first three design priorities are: establish exact supported port/kernel/guest compatibility and license/source/ABI/resolver closure; trace all kernel/core/session/provider allocation and upgrade paths for this one graph; establish finite independent teardown and complete byte/node/writer backing policy. They are evaluated together before choosing literal budgets or starting implementation. Do not port a new guest, select an obsolete port, change product support or request generic provisioning permission to bypass missing evidence. A nested Genode instance retains all outer-host resource obligations.
