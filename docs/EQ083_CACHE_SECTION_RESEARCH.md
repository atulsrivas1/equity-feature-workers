## Cache routing is specific to each successful open

[create.c](https://github.com/winfsp/winfsp/blob/ddca7bd5481857a65ba552f643b8776fd070836f/src/sys/create.c) applies the low-level successful Create.Opened DisableCache response bit by withholding FO_CACHE_SUPPORTED on that open. The inspected write and Fast-I/O paths then route away from ordinary cached handling when that flag is absent. This does not establish mapping denial. SectionObjectPointer assignment remains independent of that bit.

[fsop.c](https://github.com/winfsp/winfsp/blob/ddca7bd5481857a65ba552f643b8776fd070836f/src/dll/fsop.c) does not explicitly set DisableCache on the normal high-level Create/Open branches. A future actual integrated provider would need fixed low-level Create operation policy covering every successful disposition, open and reopen, preserving error/reparse semantics. No wrapper has been implemented; do not add an isolated cache flag wrapper and call it an enforcement boundary. The operation-context API and limited originating PID helper do not supply universal write caller identity. Opening rights must bind retained physical process instances and contexts; outside handle transfer/inheritance remain separate unresolved gates.

## Section callbacks synchronize lifetimes

[callbacks.c](https://github.com/winfsp/winfsp/blob/ddca7bd5481857a65ba552f643b8776fd070836f/src/sys/callbacks.c) contains FspAcquireFileForNtCreateSection: a void callback acquiring the node's exclusive Full lock and setting CreateSection thread bookkeeping. Release clears that state and releases the lock. Modified-page write, cache flush and lazy-write callbacks synchronize locks/thread/top-level state. They do not dispatch a user-mode mapping authorization request or implement a universal refusal. The registrations in driver.c and declarations/state in driver.h agree with these bodies. The previously guessed fastio.c path is absent; callbacks.c resolves that implementation-path gap.

[Microsoft's FSFilter section-synchronization contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/flt-parameters-for-irp-mj-acquire-for-section-synchronization) says SyncTypeOther cannot fail and describes STATUS_INSUFFICIENT_RESOURCES for insufficient memory in SyncTypeCreateSection. It does not establish a general STATUS_ACCESS_DENIED mapping policy. This FSFilter interface must not be conflated with WinFsp's void Fast-I/O callback. No unsupported minifilter-denial shortcut is selected or implemented.

DisableCache is therefore a cache-routing control for an open, while section, paging, deferred and deleted-open/replaced-object lifetimes still require accounting or a separately supported exclusion mechanism. Process exit, namespace removal or a flush return is not evidence of final native reclamation. Preserve quota reservations until real final release and retain provider/root authority through bounded drain and nofollow residual cleanup. Void Cleanup/Close inconsistency poisons the owner and cannot become a later PASS. Existing child job memory/CPU limits do not cover kernel cache, driver allocations or unrelated provider processes.
