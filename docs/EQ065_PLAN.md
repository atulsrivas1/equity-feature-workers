## Mathematics, identity and measurement

No feature formula, units, cutoffs, eligibility, initialization, coverage, Task/Output/Result/Receipt codec, source entitlement, mandatory dependency or sink-lock change. Diagnostics are bounded observational sidecars. Original task/input/config/result/evidence/receipt bindings remain exact; a diagnostic flag never certifies computation, commit, generation completeness or catalog acceptance. Existing actual SDK readback and catalog verification remain authoritative.

Measure elapsed operational work with integer nanosecond differences of Python3.12 perf_counter_ns on the same local Windows/Linux host. Counter origins are undefined; values are not UTC or market/knowledge time, and integer nanoseconds do not imply nanosecond resolution. Record clock implementation/resolution and measurement boundaries. Python documents this counter as system-wide (Windows since3.10), including sleep; inspect [time documentation](https://docs.python.org/3.12/library/time.html#time.perf_counter_ns) and [executor documentation](https://docs.python.org/3.12/library/concurrent.futures.html). No cross-host clock comparison or hard callback timeout.

Job elapsed=end-start. Stage durations are end-start for actual operations, never estimated missing stages. Concurrent calculation/serialization/queue intervals overlap: sum(stage durations) can exceed job elapsed and must not be called elapsed wall time. Frozen independent illustration: acquisitions17+17, calculations29+29, serialization7+7, publication31+31 and queue waits1+4 ns total173 versus job136 ns. These are literal test-clock values, not performance measurements.

Acquisition includes adapter admission, bounded delivery/validation and sealing; factories are separately identified when configured construction is observed. Calculation wraps the worker's pure callback invocation, leaving calculation packages free of clocks and I/O. Result validation/serialization identifies exact existing-codec work and bytes. Publication spans coordinator submit/drain/actual receipt/readback, with explicit included backend conversion/locking work. Queue wait starts at actual enqueue/submission and ends at processing start; process queue observations include startup/IPC/scheduling and are not a claim to isolate those costs. Child observations return bounded immutable sidecars, never a shared recorder or source/sink handle. Actual nonblocking BUSY attempts record lock-contention count/probe elapsed; no fabricated OS lock-wait time or hidden backoff. Generation/catalog/dependency observations retain their distinct visibility meanings.

## Public API and bounds

Proposed typed StageTiming, TaskDiagnostic, DiagnosticSnapshot and creating-thread-owned bounded ProgressRecorder, plus explicit optional telemetry in existing worker composition/supervision/publication entry points. Default calls preserve their existing behavior and outcomes. Exact frozen task hashes and family/partition identities bind observations; pre-acquisition intent is distinguished from sealed observed-input task identity. Reports contain fixed statuses/reason codes and counters, never exception text, credentials, config payloads, source paths or arbitrary callback reprs. Caller labels remain caller-owned; no automatic publication or file/network access by recorder.

Status observations distinguish ready/waiting/computed/verified/failed/cancelled/catalog-accepted work. Committed sink output, complete immutable generation and accepted catalog selection remain separate. Missing/incomplete/unknown/corrupt/BUSY readback cannot become accepted. Original failure codes are normalized from a closed known set; unknown callback errors use fixed stage-appropriate reasons. Source/factory/capability and task failures remain scoped so unrelated eligible work can continue. Retry/recovery must preserve original receipts/results and avoid a second begin after verified commit.

Defaults:64 task observations,4096 spans,4MiB serialized report budget; exact positive integer admission, bool rejected. Reserve bounded reporting capacity before side effects, enforce creating-thread/reentry boundaries before callbacks, retain immutable snapshots and clear phase ownership on errors. Process transport includes actual sidecar bytes under existing resource reservations. Measurement/reporting faults cannot invent elapsed values or erase an actual durable receipt; explicit unavailable observation remains distinct from work outcome. No unbounded log stream, dropped-task success, hard RSS, persistent diagnostic store, cleanup, source authentication or new scheduling guarantee.
