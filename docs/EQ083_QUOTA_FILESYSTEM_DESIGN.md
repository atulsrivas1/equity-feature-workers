## Proposed storage state and invariants

This is an original candidate adapter contract to be implemented within ONE integrated outer-owner/controller/entry package. It is not a generic caller-selectable quota policy, admission map or isolated Python counter wrapper. The eventual owner must freeze numerical bounds from the complete per-form source/archive/generated-map budget before Ready. Symbols below are design variables, not guessed operational constants or accepted caller arguments. Existing child CPU10s/active2/job-memory1GiB source limits remain their actual scoped guarantees; do not silently change them or treat them as driver/cache limits.

Let B be the frozen retained-storage byte bound, N the live-node bound, H the open-context bound and Q the outstanding request/buffer bound. Distinguish these from cumulative application bytes written and kernel/driver/cache RAM. Define L as EVERY live object, including directories, pending creates, detached deleted-open/replaced targets, contexts and any object with an outstanding callback, mapping or provider reference. A name-map entry is not the unit of ownership.

Maintain Ncharge = live nodes + reserved pending nodes. Bcharge = actual rounded data reservations + all temporarily overlapping old/new storage during replacements/reallocation + scratch/buffer reservations in the selected accounting domain. Hcharge counts retained opening contexts until real final release; Qcharge includes queued/in-flight requests and asynchronous buffers. Metadata/node/security/name storage needs a separately charged fixed slab/pool or explicit M bound. No variable-sized uncharged allocation is permitted in the adapter. Each charge must belong to exactly one retained object or pending transaction, including failure states. Derive alignment with overflow-safe arithmetic before acceptance; no wraparound or allocation-before-reservation.

Under ONE global synchronization boundary, every resource-increasing mutation first computes its entire worst-case delta, checks all caps, reserves, then allocates/updates and commits once. Failure returns the reservation exactly once only after no allocation/reference remains. Reallocation must charge actual overlap, not merely new-minus-old size when the allocator can temporarily retain both. A preallocated fixed pool is a possible implementation, not an existing native guarantee. Coarse upstream locking is a candidate, but no asynchronous work may outlive the lock without retaining its explicit reservation. No detached slow-I/O threads or sample delayed dispatcher mode.

The invariant is Ncharge<=N, Bcharge<=B, Hcharge<=H, Qcharge<=Q, and any chosen Mcharge<=M at EVERY accepted transition. It does NOT by itself bound cumulative writes, cached dirty pages, native kernel allocations, IPC buffers or non-adapter allocations. All such resource domains need a separate supported hard boundary in the complete owner topology. If a required domain cannot be bounded, that topology remains unsupported/denied. Do not weaken an unfulfilled hardcap to polling or endpoint snapshots.

## Mutation and lifetime transaction matrix

| Operation | Required accounting and identity rule |
| --- | --- |
| Create/Open | Bind actual opening token/process instance to an owned root role and allowed rights; retain the object/context identity. Reserve node, opening context, metadata and initial allocation BEFORE making a new name visible or returning success. Opening an existing object reserves its context independently. |
| Write/append/growth | Validate retained context/right/generation; compute overflow-safe end and actual aligned capacity. Reserve all growth/scratch before acceptance. Append chooses EOF inside the shared synchronization boundary. Constrained paging writes cannot extend the charged extent. |
| SetFileSize/allocation/overwrite | Account growth through the same transaction; a shrink releases only genuinely freed allocation. Supersede/replacement must not erase an old object's charge while its references survive. |
| Rename/replace | Update namespace atomically; the replaced target becomes a charged detached object until final release. Deny cross-root, unowned target, unsupported naming and identity changes. No copy-and-delete shortcut. |
| Delete disposition/Cleanup | Remove namespace binding only when semantics require it; retain all live-object/allocation/context charges. Void Cleanup cannot retroactively report a rejected resource increase. Any internal inconsistency poisons the filesystem owner. |
| Close/final free | Release exactly the actual reference/context and release storage/node charges only after final native/provider lifetime permits real reclamation. Double-close, missing owner or unaccounted reference is terminal denial. |
| Flush/mapping/paging/volume stop | Explicitly account and drain outstanding cache/section/request lifetimes. A flush return or process exit alone is not a final-release witness. Do not free quota while delayed activity remains. |

Named streams, reparse points/links, EA/WSL/device controls, cross-volume rename, arbitrary security changes, dynamic feature negotiation and unknown allocation paths are unsupported by this initial candidate. They must be disabled with verified native semantics, not ignored in the ledger. Full kernel/driver request coverage and section-creation/cache behavior still require exact source and native proof. No universal mapping denial or complete cache-RAM bound is established by this design.
