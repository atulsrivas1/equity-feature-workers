# Supplied-input comparison method

This harness implements the prospective [accepted EQ140 contract](https://github.com/atulsrivas1/equity-features/blob/77249cb18aea21d4b21eeb2b380b291ccae4d130/docs/stories/EQ-140_BINDING_CONTRACT.md). It introduces no default scheduling choice. Measurement remains pending until actual reviewed frozen execution; development admission checks and guard tests are not performance results.

`tools/benchmark_supplied_inputs.py --output <new-owned-directory>` requires Windows, clean committed source and actual fresh installed six-package distributions. It rejects editable/outside-environment origins and installed worker bytes differing from the measured source. Original independent guard fixtures validate the expanded geometric EMA/Wilder oracle and centered band moments. Preflight compares all eight direct results against that independent Decimal350 oracle, then actual SDK commit/readback and conservative400000 receipt headroom. Complete SDK result/output digests freeze metadata, quality, evidence and bindings; direct-versus-worker parity is additional evidence.

Every fresh runner receives the exact frozen expected-file SHA and admitted installed maps. Before computing it hashes those exact expected bytes and compares actual six-package installed namespaces/files/import origins; after computing it repeats both checks. The completed phase record is persisted before post-validation, so a changed runtime or expected file preserves measured phase evidence as failed and cannot establish adoption. The parent also verifies each completed runner's binding hashes. These checks bind declared files within the trusted environment; they are not whole-host attestation. Compute counter boundaries exclude before/after runtime checks; cold E2E includes runner verification and report persistence, with separate reference/runtime-admission and post-phase-validation observations. No estimated overhead is subtracted.

Synthetic closes are `100 + 3*(i mod 11) + (floor(i/11) mod 7)`, high/low close +/-2, explicit ten-nanosecond governed slots, period20, band multiplier2, evidence0, separate symbol identities. Workloads are small1x256, balanced16x1024 and skewed15x256+1x1024. No acquisition or proprietary data. All eight features stay one compatible shared request within each symbol. Dependencies remain real; no artificial per-feature scheduling or same-symbol parallelism is claimed.

The exact comparison uses two warmups and seven retained samples per series/profile/mode/degree. Degrees1/2/4/8 are clipped to actual allowed affinity minus one backend slot before timing. Task/in-flight/CPU/input/resident/result/transport/publication limits follow the accepted contract, including maximum sampled memory min(1GiB,25%initialfree). Logical reservation is separate from physical sampled working set and imposes no physical host-memory limit.

All six sequential baselines finish before any candidate. The harness refuses incomplete or candidate-contaminated baseline freezing, writes immutable baseline bytes plus their SHA256, then runs every admitted thread/process alternative. Warmups and failures are retained separately. Candidate comparisons require exact stable task/result/output/diagnostic/row accounting parity. Diagnostic durations, actual mode/degree, reservations and observations remain separate. Guard tests cover inclusive IQR, nearest-rank p95, strict noise threshold, CPU/memory/tail refusals and unresolved zero-CPU baselines.

One owned Job per individual sample contains the suspended-admitted fresh runner and descendants, with no breakaway and retained accounting through final descendant exit. CPU includes terminated members. Fresh pool startup/shutdown remains within execution; no persistent-worker latency follows. Actual whole-job CPU and native process counts include Windows venv launchers. Native rejection/orphan/short-child controls precede timing. Probe errors and concurrent sampled RSS are retained; unavailable required memory evidence invalidates adoption. Whole-Job sampled peak RSS is conservatively used in both series, including startup/preparation outside the compute interval. It is neither peak private commit nor the sum of separate lifetime maxima, and can miss transient peaks/short-lived processes.

Compute-only uses actual Job counter deltas after immutable source/task admission through worker/preparation/IPC/SDK validation, result checks, diagnostics and pool shutdown. Source construction/imports and sink work are excluded explicitly, not subtracted estimates. E2E starts before runner creation and ends after all descendants exit and authoritative report readback; final whole-Job CPU includes imports, source construction/admission, execution, publication/lookup/full readback and report writing. Original direct result/oracle preflight occurs once outside sample timing. Runner import and source-admission observations remain separate. External observer CPU is reported separately. SDK encodings and pickled input sizes are actual byte observations; the harness does not claim to count every physical copy or turn overlapping probes into exclusive stages.

Adoption per named series/profile requires wall improvement strictly above max(5%,3*inclusiveIQR(A)/median(A)), median aggregate core-seconds <=1.25A with resolved positive A, maximum sampled RSS within absolute budget and <=1.25A, complete resource evidence and matching small-case nearest-rank p95 <=1.10A. Every nonwin remains recorded with sequential fallback. No automatic mode change, Linux speed claim, fastest ranking, provider/live guarantee or physical durability follows. Both-platform package/correctness acceptance, separate final review and actual release gates remain mandatory.
