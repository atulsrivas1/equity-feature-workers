## Literal audit schema and stages

Each canonical audit record has exactly: sequence (nonnegative integer<=2^63-1), time_ns (integer0..2^63-1), stage (attempt/finish/native_start/native_finish), actor, command, grant, policy (null or32lowercasehex opaque epoch-HMAC references), action (fixed operation enum or unknown), decision (fixed code below), request_used, transfer_used, transfer_reserved, retained_used, cache_used (nonnegative integer<=2^63-1). There is no raw caller correlation or exception field. Each actual canonical record must fit512bytes. Opaque references are first16bytes of HMAC-SHA256 with a fresh32byte secret/epoch and domain-separated bounded server strings; they are diagnostics only, never cache/auth identities. Secret and original credential digest are never included in records. Unknown unauthenticated actor/command/grant is null. Policy reference is hashed; no arbitrary text enters record.

Fixed decisions: admitted, emitted, denied_auth, denied_contract, denied_quota, internal_failure, abandoned, started, succeeded, failed, cancelled, expired, historical_commit. Fixed actions: discover/slice/calculate/job_status/job_cancel/result_read/artifact_read/unknown. Raw error messages and unsupported operation strings map to fixed categories.

Reserve two512byte record slots per HTTP attempt before protected preparation: attempt and finish. A newly admitted native job also reserves two512byte slots for native_start and native_finish. A repeated idempotent request reserves its HTTP pair only; no duplicate native audit pair. Reserved slots count toward128records/65536bytes until settled/released and across fixed request interval resets. Settle actual canonical bytes, release unused worst-case difference once. Finish is emitted/denied/abandoned exactly once through iterator emission or close; an abandoned prepared request cannot hold an unbounded full payload. Native slots remain held until actual native exit, including cooperative cancellation. Expired queued cancellation settles native pair without fabricating execution; start decision cancelled, not started. Cleanup cannot prematurely free slots still needed for active work. Emit only after reserved audit finish can settle safely under the same ledger visibility lock.

No recursive auditing on exhaustion: if an attempt/native pair cannot reserve or encode within512bytes, deny new protected work before native execution/visibility, increment only a fixed saturating overflow counter, and return the usual bounded quota/internal denial subject to existing transfer allowance. Never silently allow work while auditing is disabled. Counter<=2^63-1; saturation remains fail-closed. No eviction/overwrite of unexpired records. TTL is half-open record_time+300seconds maximum; metadata maintenance and synchronous reads purge expired completed records. No disk/backup retention. Invalid clock denies new work and audit read, preserves reservations until safe exit/explicit epoch end, and increments bounded failure counter without caller text. Pending records are reservations, not retained historical records; expiry cannot allow active unrecorded success.
