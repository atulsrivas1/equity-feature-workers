## Mandatory cleanup transfers ownership

[cleanup.c](https://github.com/winfsp/winfsp/blob/ddca7bd5481857a65ba552f643b8776fd070836f/src/sys/cleanup.c) creates a MustSucceed request because the cleanup IRP cannot fail. The path transfers the node Full lock to request-finalizer ownership before best-effort posting. Its finalizer performs CleanupComplete even when delivery is cancelled or dropped. Therefore delivery of a user callback is not the only lifecycle completion path. An eventual resource contract must retain the request, lock, node and cleanup obligations through the actual finalizer; it cannot assume cancelling delivery erases ownership.

[close.c](https://github.com/winfsp/winfsp/blob/ddca7bd5481857a65ba552f643b8776fd070836f/src/sys/close.c) constructs a NULL-IRP MustSucceed request, closes/deletes the kernel descriptor and dereferences the node before posting. Rename context or a pending watermark can retain the original IRP for best-effort synchronous posting; otherwise an internal best-effort work IRP permits the original Close to return. This is a concrete outstanding-debt path after descriptor release. It is not evidence of an actual leak, unbounded execution or a demonstrated runtime failure.

## Request allocation and final release differ from file close

[iop.c](https://github.com/winfsp/winfsp/blob/ddca7bd5481857a65ba552f643b8776fd070836f/src/sys/iop.c) adds request header/alignment/name/extra-data allocation and optional work-item allocation. The best-effort work path allocates another internal IRP. STATUS_PENDING transfers request ownership; a nonpending/failed post retains ownership and deletes the request. Completion frees the internal IRP. DeleteRequest invokes the finalizer, then frees retained response, work item and header allocations. Those are distinct lifetime transitions and charges.
