# Declared dependencies and universe barriers (experimental 0.1.0a5)

[EQ060 #68](https://github.com/atulsrivas1/equity-features/issues/68), [pre-code plan](EQ060_PLAN.md), [delivery](EQ060_DELIVERY.md). Retains the [required-input commands](REQUIRED_INPUT_COMMANDS.md), [session commands](COMMANDS.md) and existing [task protocol](MANIFESTS.md). No core mathematics, schema, codec or IO change.

`Dependency(instance_id, task, output=None, sink=None, required=True, optional_policy="wait")` declares the exact expected TaskManifest and a caller-owned candidate OutputManifest and sink. Output=None requires sink=None and represents explicit absence; the worker does not discover files, backends or undeclared jobs. Supplied output must own exactly that expected task. Instance IDs and task identities are unique within a barrier. Optional absence requires required=False and optional_policy="allow_absent"; default optional policy waits. No factory or backend error becomes absence.

`BarrierLimits(max_dependencies=64, max_bytes=8388608)` bounds concrete declared dependency counts (maximum4096) and combined admitted task wire/result bytes. `inspect_barrier(dependencies, limits=..., requirements=..., cancellation=...)` validates the whole declaration and quota before callbacks, uses existing SDK sink admission, looks up each declared envelope key and reads the actual committed receipt's logical result. It verifies receipt/content/descriptors/metadata, exact expected entity-feature population and provided receipt equality. A supplied committed flag does not satisfy the barrier. A staged candidate envelope can qualify only after lookup supplies a valid actual committed receipt and readback.

| Observation | Barrier behavior |
|---|---|
| Explicit absence or lookup ABSENT | Required/default optional waits; declared optional allow_absent is omitted |
| STAGING, ABORTED, UNKNOWN | Wait with that explicit reason; never infer rollback or optional absence |
| Actual COMMITTED plus correct logical readback | VerifiedDependency carries the actual CommandOutcome |
| Lookup/readback/receipt/content/entity failure | Safe scoped waiting/fault reason, no verified dependency |
| Cancellation | Raises CANCELLED cooperatively; no aggregate publication |

`BarrierOutcome` retains declarations, verified dependencies, waiting instance/task/reason records and explicitly omitted instance IDs. `ready` means no waiting dependency in that barrier; it does not certify physical storage, claims or accepted-generation/catalog state. Backend exception details are discarded. Fault reasons use the existing safe command vocabulary. Sink lookup/readback faults are contained to their dependency, so independent work can continue; invalid static declarations fail before any callback. The next supervisor/observability stories own execution and structured progress, not this synchronous admission function.

`TaskNode(task, required=(), optional=(), optional_policy="wait")` declares dependency task SHA identities. `evaluate_readiness(nodes, dependencies, limits=..., requirements=...)` rejects duplicates, unknown edges and cycles before lookup. Its count limit includes nodes and declared dependencies, and its byte admission includes task/output wires, edge/instance/policy records and readback declarations. Each node has at most4096 edges. It returns deterministic ready tasks in declared node order: only a node's required and selected optional edges must qualify. Completed nodes are excluded; optional omission satisfies only an allow_absent optional edge, never a required edge. A waiting or corrupt history/reference/universe dependency does not block an unrelated root. This layer takes supplied expected frozen task identities; it does not discover/acquire unknown inputs or map an unsealed acquisition request to a task. The caller maps admitted tasks to explicit runnable commands; execution strategy remains EQ062. No background execution, process/thread sharing, source fetching, global readiness latch or implicit history edge is introduced.

`run_assembly(composition_spec, dependencies, components, limits=..., requirements=...)` requires exact ordered instance declarations from the public CompositionSpec. Supplied FamilyResult objects must match expected tasks, config/full history bounds/inventory/source bindings and actual readback results. When a required dependency waits, the outcome has bundle=None. Once admitted, public compose_features preserves complete owned families/configs/contexts/companions in declared order and explicit optional missing instances. FeatureBundle remains an in-memory collection of committed components, with its existing public identity_digest. It is not a new SDK persistence format, completion marker, immutable-generation publication or catalog selection. EQ061/EQ064 own those outcomes.

`UniverseShard(shard_id, member_ids, dependency_ids)` assigns a nonempty disjoint member population and all explicitly consumed dependency instances to that shard. `BreadthCommandSpec` binds job/generation/partition, closed family direction_counts/above_sma_fraction, canonical config, exact governed intervals, revision/destination/input-byte budget, caller DeclaredUniverseSpec/BreadthSpec and shards. All shards together must partition the exact declared universe, with no omitted, duplicate or extra member/dependency/shard ID. Every dependency's actual declared instrument population must belong to its shard and the shard's declared dependencies must cover its member population. Multiple required result dependencies per member are allowed, including a distinct declared close source frame; source lookup is explicit, never inferred from member names. Empty explicit universe uses zero shards and preserves the public empty-universe result.

`run_breadth(spec, dependencies, members, sink, limits=..., requirements=...)` first admits exact member/proof/dependency associations, full grid/target/C-K-E and consumed period/unit/adjustment/backend/context alignment. Only consumed fields affect readiness and identity: direction uses ReturnReference; above-SMA uses SMAInput/CompletedClose. Each selected owned return/SMA result must match a declared task and actual committed readback exactly. A close's original source binding must match a declared result's admitted input provenance. Caller still owns that close's original coefficient/row/known-at/certificate; result publication does not authenticate raw source prices or exact witness operands. Qualified replay or supplied owned proofs are needed after resume, never rounded-scalar reconstruction. No new witness codec, calendar/membership lookup, implicit calculation or raw-source acquisition is performed.

No aggregation occurs until required receipts/readbacks cover every shard and member. Waiting returns BreadthOutcome with command=None and breadth=None. A committed canonical unavailable value or explicitly missing close is different from a missing task: all task receipts can be present while public mathematics excludes an ineligible member, preserves expected |U| and emits incomplete_coverage/partial_universe with typed exclusions. Invoke public compute_direction_breadth/compute_above_sma_breadth only after the barrier; retain exact strict close>SMA comparison and fractional eligible denominator. Hash consumed owned universe/shard/proof/task and actual committed key/content declarations into the final task. Publish its ordinary FeatureResult with the shared SDK publisher and verified logical readback, returning the existing owned BreadthResult alongside CommandOutcome. No competing result or receipt schema.

The installed caller-injected CLI adds `--assembly` and `--breadth direction_counts|above_sma_fraction`. It requires explicit owned objects/dependencies/limits; no default backend. Waiting output has ready=False and safe waiting records, without a successful aggregate readback flag. Assembly reports components_verified_readback and the owned bundle identity/results/missing list, explicitly without generation/catalog acceptance. Breadth success uses the existing SDK result wire and receipt/task digests, plus an owned-witness type/exclusion-count diagnostic. CLI diagnostics do not persist or reconstruct companions. The Python API retains all exact proofs/exclusions.

Checkout tutorial using installed packages and the separately frozen synthetic fixture helper (tests are not a runtime dependency):

```python
from test_barriers import inputs, BOUNDS
from equity_feature_workers import run_breadth
from equity_feature_example_extensions import ExampleSink
from equity_feature_example_extensions.sink import LIMITS

spec, dependencies, members = inputs(direction=False)
outcome = run_breadth(spec, dependencies, members, ExampleSink(),
                     limits=BOUNDS, requirements=LIMITS)
cell = outcome.breadth.result.values[0].values[0]
assert (cell.above, cell.eligible, cell.expected) == (1, 3, 3)
```

The [pre-code oracle](../tests/barrier_oracle.json) and [installed tests](../tests/test_barriers.py) cover counts1/1/1, exact1/3, optional/wait/fault scope, receipt/readback/entity/grid guards, complete shards and exact half-tick comparison near2^53 where persisted floats compare equal. Limits bound admitted declarations/encoded results, not hard process RSS. Owned proof hashing/canonical validation can copy caller records; trusted synchronous callbacks may allocate/block before return. Cancellation is cooperative, not preemption/timeouts. Reader/writer ownership, retention, immutable generation coordination, durable claims and catalog selection remain distinct later stories. No synthetic test establishes private-source/month/annual-generation readiness, physical backend certification or speed improvement.
