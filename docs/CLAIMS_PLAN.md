## Ownership and timing

ClaimStore is caller-owned trusted local Windows/Linux operational metadata, separate from sources, sink storage, generations and catalog. Claim keys bind exact existing Task SHA256, including observed source/config/revision/cutoff bindings. Claiming requires a supplied sealed task; this API does not deduplicate acquisition before observed identity exists. A changed input/config Task is different work, not a silent replacement.

Reuse ClaimIdentity(task SHA,owner,attempt,issued UTC ns,expires UTC ns); explicit caller time t admits issued<=t<expires. Expiry stops subsequent steps but never steals a live OS lock or preempts callback work. A stable per-task lock is held for the entire attempt through publication and metadata finalization; duplicate owners receive BUSY. OS process exit releases ownership. No lease-only takeover while an older publisher can run. A hung owner requires caller cancellation/process handling; no hidden watchdog or wall-time scheduler. Thread-object ownership and closed-handle checks fence stale local handles. Lock files are retained and never replaced/deleted. A separate bounded metadata lock serializes inventory/update/cancellation, never held over calculation/sink I/O. Qualify actual Windows byte-range/POSIX flock behavior in spawned processes, including process termination and fresh-process resume.

## Durable state and bounded retry

One closed canonical JSON operational record per exact task embeds existing Task/Output codec bytes. Record schema efworker-claim1; attempts count started calculations, not receipt checks. Default caps64 tasks,8MiB aggregate canonical records,1MiB per record,3 computation attempts,4096 hard task cap. Bounds and integer admission precede callback/sink begin. Inventory and updates are admitted under one stable writer lock. Unknown/corrupt records reject and preserve bytes. Exclusive temporary writes, flush/fsync then same-directory replace; interrupted temporary files retained, no recursive deletion. Logical active-record quotas do not bound all interrupted temporary disk bytes or decoded/interpreter memory. Root must be local, nonsymlink, disjoint from declared source paths in both directions; caller owns filesystem security and mounted-filesystem truth.

States CLAIMED,FAILED,CANCELLED,INTENT,COMMITTED are operational; COMMITTED never proves catalog acceptance. Before sink begin, persist exact prepared OutputManifest without receipt. A restarted owner with INTENT/COMMITTED always performs existing inspect_barrier actual lookup, receipt verification and logical result/entity readback before calculating or retrying. COMMITTED readback returns original receipt/results without callback or another begin, even after retry exhaustion or cancellation. RESERVED/UNKNOWN/BUSY/readback failure remains waiting; no blind retry. Only verified ABSENT/ABORTED permits a bounded recomputation/republication. Recomputed results must match the persisted envelope exactly; conflict preserves prior intent. A crash after sink commit but before metadata update is resolved by actual readback. No exactly-once computation/distributed transaction/power-loss/network-filesystem claim.

Each run is one bounded pass; no automatic sleep, loop, background scheduler, acquisition, stored executable callback/pickle or implicit resume. The caller supplies a trusted calculation callback, current time, existing sink/requirements and cancellation. Callback returns bounded standard results; existing SDK/entity admission applies. Fixed redacted errors retain task/owner/attempt identity and prior intent. Retry exhausted blocks new callbacks but permits recovery. Durable cancellation requests are polled at worker/SDK boundaries; started calculation can finish but publication observes cancellation. Explicit clear_cancel on a new acquired handle resumes cancelled work. Completed commitments survive cancellation and are always reverified. Callbacks remain trusted and cooperative, not sandboxed or hard-preempted.

## Independent acceptance fixture frozen before implementation

Synthetic table: owner A claims exact task at t100 with expiry200; owner B gets BUSY at199 and200 while A holds lock. A step at200 is rejected by supplied-time admission, without lock theft. After A closes/exits, B at201 with its own201..300 identity acquires. Closed A cannot change metadata/publish. Computation attempts1,2,3 allowed; fourth blocked before callback. Intent lookup precedes callback on every resume; actual committed receipt overrides cancellation/attempt exhaustion without second begin. Changed envelope conflicts. Shared-root quota race admits only one last slot. Cancellation before execution causes zero callback/begin; during callback prevents begin; cancellation after commit returns verified commitment. Two actual sinks Parquet0.1.0a1/PyArrow20 and DuckDBsink0.1.0a0/DuckDB1.5.6 each exercise crash-after-commit/restart, absent/aborted/unknown retry, corrupt metadata, owner/process contention, no premature catalog completion and independent numerical result bytes/literals.
