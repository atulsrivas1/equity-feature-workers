# Experimental catalog API — worker0.1.0a9

[EQ064 pre-code contract](EQ064_PLAN.md) defines operational identities, sequence units, serialization and scope. No numerical/core/I/O codec/mandatory dependency/sink locking change.

`CatalogStore(root, limits=CatalogLimits(), requirements=existing_sink_requirements, protected_sources=())` performs no writes. Callers own trusted local Windows/Linux paths and separate source/generation/sink roots. Stable global catalog writer ownership serializes selection, with creating-thread/re-entry fencing. Defaults64 catalogs/64 selections per catalog/8MiB active aggregate/4MiB record; maximum4096 catalogs/history and16MiB record. Exact positive ints; counts are not clock times. Interrupted UUID stages remain outside active-byte quota; no cleanup/nativeRSS/cumulative abandoned-disk guarantee.

`select(spec, generations, dependencies, expected_sequence=n, cancellation=None)` verifies actual immutable GenerationStore completion and original sink receipt/full logical result/entity readback before appending. First expected0 selects sequence1. Same current exact generation replays unchanged after live verification; stale different generation or historical reselection conflicts. Corrections use new generation identity. History and selected last entry are one closed canonical ASCII JSON record, atomically replaced from a flushed/fsynced exclusive stage in the same directory. No sink begin/write/commit or new multiwriter DuckDB capability. Incomplete/unknown/readback-fault/BUSY generation returns unaccepted outcome and preserves old selection; corrupt/conflicting records fail typed and preserved. Full history or active-byte/count limit returns RESOURCE_LIMIT without eviction.

`snapshot(namespace,job_id)` is read-only bounded metadata lookup: no directory creation/writer lock creation/backend access. Missing yields None. It returns CatalogSnapshot(namespace,job_id,history), sequence=len(history), selected=last entry and a domain-separated canonical content identity. Every CatalogEntry has original GenerationSpec/ordered OutputManifest tuple. Snapshot metadata alone does not establish usable output.

`verify(snapshot,generations,dependencies,cancellation=None)` proves the retained snapshot history is an exact prefix of current recorded history and re-verifies the snapshot's original selected generation via existing actual receipts/results. A retained old snapshot can continue reading old immutable output after newer selection. CatalogOutcome.accepted requires recorded lineage and complete verified GenerationOutcome; outputs/barrier full results remain original. Missing/conflicting lineage cannot certify a fabricated snapshot; corrupt or unavailable backend content never becomes accepted. The catalog records caller selection, not source truth/PIT/private dataset/math acceptance.

Normal reads close catalog file handles before logical validation/feature consumption. Windows sharing/access denial during replacement returns fixed BUSY, preserving old selection and complete stage for explicit caller retry after reader closes. Linux open reader can retain whole old inode bytes while new readers see new record. These are native test obligations, not network/power-loss guarantees. Existing DuckDB live foreign writer can make generation readback unaccepted/BUSY; no selection circumvents sink ownership. Cancellation before replacement preserves old state; after successful replacement cannot retract it. Writer-release failure after durable replace is fixed UNAVAILABLE; caller snapshots and verifies actual current state before retry. Every cancellation callback poll requires exact bool, exception/non-bool -> redacted INVALID_CONFIG. Generation/config/dependency validation precedes catalog file creation.

Run source synthetic example with PYTHONPATH=packages/workers/src, then `python tests/catalog_example.py`. Installed qualification runs the same example under isolated Python against site-packages. It publishes A/B, retains oldA snapshot, verifies original .2/- .2/0 full results with zero new sink begin. Public tests use synthetic Apache fixtures only. Source/fresh-form/native/separate-review/actual-main/receipt/archive parity gates are pending until tracked [delivery evidence](EQ064_DELIVERY.md) records them. Experimental successful-main artifacts only; no stable registry release.
