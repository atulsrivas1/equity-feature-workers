# Synthetic agent research example

EQ109 is an experimental external source example, currently In progress. It uses the accepted optional evidence, explanation, diagnostic, bundle, event and local ledger APIs. It adds no package version, numerical feature, remote handler or agent framework. R11 has not been released.

The supported data is deliberately narrow: one caller-owned three-row A/S trade fixture, its fixed configuration and five complete output/quality rows. The separate pure late-known variant has last known time211 versus cutoff210 and produces five unavailable values. All inputs are synthetic. Full retained-content consistency does not authenticate the source or prove original consumption/execution.

The narrative grammar is exactly `session.trade.count=<nonnegative decimal integer>` within128ASCII bytes. Count3 matches,4 mismatches, free prose is unsupported. This is a deterministic fidelity check, not natural-language reasoning. The selected unknown advisory diagnostic always has `admission=not_applied`: the example returns DEFER or REJECT, even when input content, replay and ledger anchors all match. It never grants trading authority or human approval.

`examples/agent_research.py` defines the immutable Assessment and separate replay/ledger observations. `assess` copies bounded, explicitly recognized public types before fingerprinting. It compares complete configuration/result/input content and full bound receipt/count-focused explanation/diagnostic bytes. Missing reports are unavailable; present inconsistent bytes refuse. Missing retained input is separately recorded as verified0of1, while the unchanged MCP explanation always leaves its input content unverified. No general explanation/diagnostic decoder is introduced.

`examples/agent_research_typed.py` demonstrates an explicit actual pure computation and replay. With the declared optional packages installed, run `python examples/agent_research_typed.py`. Importing the main consumer does not import the calculator. Complete supported replay calls the unchanged `session.compute_trades.v1` once. Reference-only input is unavailable0; a fresh calculator-absent light installation is incompatible0; explicit pre-entry cancellation is cancelled_before_start0. Changed content refuses before replay. No automatic mutation retry or replacement replay is attempted.

The worker companion `examples/agent_research_mcp.py` accepts a caller-owned initialized official ClientSession. Its fixed commands read the current original result, grant-backed producer/receipt/explanation/diagnostics chunks and compare advertised output schemas and exact response text/structured content. Remote configuration, origins, credentials, provider callbacks, arbitrary code and ledger paths are not tool arguments. Native backend grants remain authoritative. MCP descriptor `input_content_verified=False`, source/execution flags and native TTL semantics remain unchanged; the outer supplied-content comparison is separate.

Each observed public tool response text is retained separately from assembled reports. Every actual call and continuation produces a ToolCall/ToolResult pair, at most32pairs/68events. Initialization/discovery and owner preparation are separately witnessed, not labeled complete agent history. Unknown model identity and caller times remain unauthenticated. `record` appends each event exactly once against its expected checkpoint; unknown outcomes propagate for accepted manual reconciliation. It never retries an append.

A terminal digest must be calculated independently before append and retained outside SQLite. After closing/reopening, verify the complete chain and contiguous pages against that terminal. A valid shortened prefix can remain internally consistent while not covering the external terminal. Payload retention requires checking the actual referenced bytes; a caller boolean, content hash declaration or chain match is insufficient. Missing input/report/model/anchor/retention states remain separate from replay status and overall research decision.

Application limits include4096typed nodes/depth16, known-class fields,64element tuples,128ASCII labels, three input rows, report32KiB each/64KiB aggregate, event16KiB and bounded chunk/frame/call counts. These are application limits, not total physical memory/storage quotas, hard callback/kernel deadlines, hostile-Python isolation or power-loss guarantees. The local ledger requires a caller-owned trusted absolute path. Redact before append; corrections do not erase original plaintext/backups.

Source development checks and strict typing are separate from fresh installed qualification. Four fresh forms on bothOS, actual official SDK/native composition, full selected source/metadata/license/RECORD maps/current artifacts and independent public-main release evidence are still required. Earlier failed reviews/checks are preserved, not relabeled as successful runs.

The selected explanation is reference-only, as required by the accepted MCP catalog. `content_verified=False` and the `input_content_unverified` explanation finding are preserved. The outer Assessment checks supplied input bytes independently and can report verified1of1 without changing either that report or the MCP descriptor. The initial incompatible fully supplied explanation was caught by ordinary source preparation; its failed log and correction are retained.
