## Topology and authority

Use a modified Genode26.08/NOVA/VirtualBox7 family only as a proposed baseline. The actual effective boot/kernel/build, hardware interrupts/clock/CPU membership, vendor archive/SDK/30patch/generated output and both guest OS images remain unselected. Three trusted ownership domains are proposed: boot-root and static kernel/core reserve; independent failure controller and fixed mailbox/clock/control reserves; and one epoch containing VMM, guest RAM, storage backing and required providers. All three are inside the physical budget. Additional RAM/cap donors and external mutable service authority are denied. Fixed source/ROM image and result transfer use separately charged immutable input and bounded output regions before guest execution. Do not infer that existing parent routes enforce this topology.

The controller owns root admission and the epoch's immutable manifest. The guest and VMM cannot change root config/routes, acquire new donors, enlarge pools, activate outside device writers or modify the controller. No host shared folder, clipboard, USB, network bridge, physical-disk backend, passthrough/DMA, outside log sink or GUI provider is admitted. Guest loopback TLS/HTTP remains inside the guest; external network is unnecessary for the qualification dialogue. Headless execution and the fixed input/result-transfer mechanism require actual supported effective implementations, not a sample config claim.

## Ledger and phase contract

The physical total must cover boot/static kernel/core/controller reserves plus the entire epoch: guest RAM and page tables, VMM heaps/stacks/metadata, capability/IPC/signal objects, all provider buffers/queues, immutable and writable images, node metadata, temporary generations and deferred/retired debt. Every term needs measured or proved literal geometry and an actual reservation issued before acquisition. No symbolic sum is an admitted budget; no missing class defaults to zero. Transfers conserve debt. Refunds occur only after actual release, with overlap charged to both generations. Numeric values are deliberately unset because the effective implementation is not qualified.

Proposed phases are RESERVED → VERIFIED → RUNNING → STOP_REQUESTED → SETTLING → CLEANED or FAILED_RETAINED. Admission, output and reuse are separate gates. FAILED_RETAINED keeps ownership and denies all new mutation/admission; it must not falsely assert physical quiescence or settlement. CLEANED requires all execution/writer/queue/reference/finalizer and nofollow-root evidence. A missed deadline/unknown live resource/void cleanup inconsistency denies. No endpoint/path/counter-only evidence promotes either terminal state to success.
