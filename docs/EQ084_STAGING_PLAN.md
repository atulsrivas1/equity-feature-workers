## Deployment design

Use one existing operator-approved Windows or Linux staging host/account and a new disjoint owned deployment directory. Install the immutable artifacts qualified by EQ083 with a private isolated environment, fixed interpreter/package/archive/registration/configuration identities and synthetic inputs. No arbitrary uploads, private providers or new dynamic registrations. One service epoch and fixed approved worker processes only; replacement requires observed old execution shutdown and declared cleanup outcome. Bind the experimental accepted service to loopback; any remote operator access uses an explicitly approved private SSH/tunnel path, never an Internet-facing service. Preserve the accepted qualification handler's duplicate-header and bounded-body behavior and reviewed TLS-accepted-socket timeout/certificate handling; do not silently substitute a different WSGI parser.

The accepted qualification_server is local qualification only. A private hosted staging wrapper/launcher, immutable operator configuration and access arrangement need exact source/operation review. Record the limited scope as an experimental operator-only staged deployment. A public/production hosting claim requires a separately selected and qualified front end/threat model and permission; it is excluded here.

Server TLS keys and bearer credentials are generated or supplied under the selected operator's approved private ownership; only public certificate pins/nonsecret configuration are published. Logs/audits redact caller strings, credentials and provider exception text. Native callbacks, source/sink and calculations retain accepted separation; mathematical definitions remain unchanged.

## Exact operational drills after approval and EQ083 acceptance

1. Deploy a qualified immutable bundle/configuration to the new owned staging root; record artifact/config/data digests, real process/endpoint identity and baseline authenticated public HTTP/client/MCP result parity against frozen synthetic expectations.
2. Roll out a separately approved changed configuration/bundle, observe its exact advertised/admission behavior, then restore the known-good bundle/config. Verify old epoch references fail and new explicit computations match expectations. A source diff or a reboot without observed rollout/rollback is not evidence.
3. Run bounded fixed-fixture concurrent load against declared request/job/result/process/accounting limits; record request totals, observed queue/capacity/denials, latency samples and actual cleanup. No saturation of unrelated host workloads, unbounded loops or claimed SLO/hard physical ceiling.
4. Execute negative authentication/authorization, wrong versions/bindings, cross-principal access, expiry/revocation, malformed/framing/body-bound and inert-error tests through the real staged endpoint. No uncontrolled penetration scans or arbitrary code execution.
5. Back up immutable nonsecret deployment/configuration/input/result-store material to a new operator-approved private location, verify its complete byte/hash manifest, then restore to another new owned directory and actually redeploy/recompute. Secrets/keys follow the explicitly approved operator recovery/rotation procedure, never public archives. Do not promise recovery of volatile scheduler/MCP job state; record expired/unknown old references and required manual resubmission.
6. Run controlled interruption/failure and recovery for owned staging processes; stop admission, observe actual exit/cleanup or explicitly fail/quarantine, restore known-good deployment and verify a fresh epoch. No unrelated process termination, host reboot/admin alteration or destruction of existing data. No cleanup witness is inferred from terminal status or endpoint disappearance.
7. Publish the tested runbook, operator/configuration/access ownership, exact command/action log with secrets removed, backup/restore/rollback/load/security evidence and independent actual operational review. Only genuine passed operations count; preserved failure/rework and limitations remain visible.
