## Ownership and first actions

Choose the explicitly bounded single publisher for a shared output destination. One caller-owned sink is used only by its designated publication owner thread; concurrent producers may submit immutable task/results to a bounded queue. Serialize whole publication attempts and retain the backend's actual locking: Parquet holds its writer lock for the whole attempt per root, regardless of partition IDs; DuckDB has one writer per database. Foreign cooperating writer contention remains BUSY/waiting; no private backend SQL/layout/lock changes or automatic shared connection access. Independent-root parallel publication is a future measured option, not silently enabled here.

Queue admission bounds pending task count and exact logical result/declaration bytes before callbacks, validates existing TaskManifest/OutputManifest/SDK envelope and actual task/entity/feature/source/timing inventory, and rejects conflicting duplicate submissions. Each bounded drain examines declared publication state, reuses SDK prepare/publish/receipt checks and actual logical readback, and retains unresolved work with explicit waiting/failure evidence. A failed or uncertain callback cannot mean absence or dropped success. Before retrying, look up the actual key and verify any committed receipt/readback; STAGING/UNKNOWN/corrupt states wait rather than overwrite. Cancellation is cooperative and its disposition remains explicit, with no completion for a cancelled/incomplete generation. Claims, scheduling policy and durable retry journals belong to EQ063; execution/resource strategy to EQ062.

Generation coordination owns operational job/generation/expected ordered task identities, not a second result or sink receipt schema. A bounded GenerationSpec declares the exact immutable tasks. Require matching job/generation and exact coverage of all expected tasks with existing Dependency/OutputManifest records; no optional omission for a completed generation. Reuse EQ060 actual lookup/receipt/content/readback barriers and their resolved metadata/shared byte quotas. A completion record stores only versioned operational generation identity plus existing encoded output records, retaining exact SDK receipts and content identities. It is not a new numerical/witness codec, accepted catalog pointer or proof of raw source truth.

A caller-owned local GenerationStore separates private staging from immutable completion, publishing completion last only after all declared outputs qualify. Serialize store publication with a stable local OS lock; use bounded canonical inert metadata, private staging and atomic completion publication. Existing completion must match exactly and may not be replaced; conflicting generation contents fail. Reader admission validates complete record identity and repeats actual receipt/readback; private/staged files alone never establish completion. Interrupted staging is not visible as complete. Retry may reuse committed immutable sink outputs and produce the same completion. Storage protocols and source files are not modified by the worker. Explicit protected source paths must be disjoint from store roots; configuration is trusted, and omitted paths are not discoverable or authenticated. No uncontrolled cleanup of existing outputs or private files.
