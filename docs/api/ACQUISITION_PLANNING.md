# Installed acquisition planning

Experimental workers0.1.0a13, canonical [EQ073 #82](https://github.com/atulsrivas1/equity-features/issues/82). Current delivery/acceptance is in that live issue; this API description is not a release or provider-access claim. Default dependencies remain SDK.a2 and pure features/contracts.a4. Concrete files/acquisition/example sink are explicit optional qualification/demo installations; worker imports do not import them.

`SourceOffer(source_id, capabilities, config)` snapshots caller-declared immutable AdapterCapabilities and flat public configuration for an existing explicitly registered SourceRegistry factory. Offer/config and plan repr are opaque. Values are exact str/int/finite float/bool/null; keys follow the existing SDK names and exclude credential/executable keys. Inventory is supplied explicitly: no module scan, import-string loading, package install, source/sink creation, path lookup, credential lookup or acquisition during planning. Registry IDs establish explicit installation/registration only; metadata does not certify factory purity or authenticate rights/coverage/provenance. Caller code is trusted, not sandboxed.

`plan_acquisition(spec, feature_ids, sources=..., offers=..., sinks=..., sink_id=..., sink_config=..., requirements=..., source_id=None)` accepts the already validated SessionCommandSpec or RequiredCommandSpec. Unique nonempty requested builtin IDs must be in the supplied command's implemented outputs. It reads their actual public InputRequirement metadata, admits the existing bounded request against kind/schema1/namespace/exact UTCns/scaled price unit/adjustment/sampling/historical/chunk capabilities, and selects one matching installed offer. Zero matches fails NO_INSTALLED_CAPABILITY; multiple matches fails AMBIGUOUS_SOURCE unless source_id is explicit. Feature definitions, capabilities and commands are reused, not copied schemas or a new registry.

`AcquisitionPlan` declares requested_features, execution_features, full selected requirements, optional source offer, sink ID/config/requirements, command_sha256 and plan_sha256. JSON hashing domains efworker-acquisition-command1 and efworker-acquisition-plan1 bind full command/context/witness contents, sorted requested IDs, declared requirements/co-produced outputs and exact source capability/config plus sink ID/config/requirements. Selected feature order and configuration dictionary insertion order do not change identity. Any command/source/sink/config/capability/requirements change changes the corresponding plan. Hashing is logical identity, not user authentication or source truth; factory closed-over state is trusted and not attested by configuration hashing. Actual source mapping/content/coverage identity is validated and retained by adapters and worker manifests.

The supported executor remains the accepted worker command inventory, not every builtin family: session BAR/TRADE/QUOTE and RequiredCommandSpec raw history/bucket or explicit supplied-context/witness/absence flows. Out-of-command/unknown/custom feature IDs fail UNSUPPORTED_FEATURE_OR_ROLE. Selected features needing a different additional canonical raw kind (for example overnight_gap requires prior_close REFERENCE as well as BAR) fail explicitly. No cross-provider composition, synthetic historical knowledge, calendars or joins are added. A request=None is the existing explicitly supplied absence/witness route, never acquired or invented data. Full command-family outputs can be co-produced from the same acquired input; plan.execution_features states them. Extra unrequested outputs may carry the existing unavailable/null status for absent facts. Selecting bar.volume does not silently acquire prior_close or claim unavailable overnight results are complete.

`execute_plan(spec, plan, sources=..., sinks=..., credentials=..., authorize=None, cancellation=None)` denies by default. The caller authorizer receives the exact opaque-repr plan and must return `ExecutionApproval(plan.plan_sha256)` after the user consents; None, wrong type or wrong hash yields EXECUTION_NOT_AUTHORIZED. Validate/recompute current command/registry/plan identity and cancellation before consent, again after callback, then construct only the selected source and sink with existing SDK resolution. Denial occurs before either factory/config-validation/credential callback or source/sink access. Compare actual constructed source capabilities to the selected declaration, in addition to SDK admission; stale/unsupported metadata cannot authorize acquisition. Cancellation is checked between stages; arbitrary caller/plugin callbacks are cooperative and cannot be preempted or sandboxed.

ExecutionApproval authorizes this exact runner plan only. It is not a provider download, license, account entitlement, cache, subscription or billing approval. Optional provider/file adapters independently enforce their scoped [EQ068 acquisition controls](https://github.com/atulsrivas1/equity-features/blob/main/docs/api/ACQUISITION_CONTROLS.md); credentials, feature selection and runner approval never grant spending permission. LocalFileFactory still requires its separate exact local-file use approval; cache retention/use remains independent. There is no implicit consent, hidden install, broad acquisition, extra retry or provider request here.

Delegation to run_session/run_required retains accepted collection limits, original coverage/known-at/nulls, task/input/result/evidence/source lineage, serialization, sink writer ownership and receipt readback. Planning introduces no algorithm or core change, process/job launch or new publication protocol. Results use the existing CommandOutcome/RequiredOutcome; no lossy reshaping or feature filtering. Source failures, sink failures, limits, cancellation, invalid/stale/unsupported/ambiguous/unauthorized plans and approval failures have fixed typed PlanningError.code; wrapped provider/caller exception text and chaining are absent. Caller-local trace/debug objects remain trusted, not a privacy sandbox.

Logical bounds: 128 feature IDs, 128 distinct offers, 64 configuration entries per selected component, 65,536 characters per string configuration value and 16MiB encoded command/plan identity. Existing requests/worker/adapter/sink limits still apply and can be tighter. Metadata hashing and callbacks are not hard RSS/time isolation or distributed quotas. There is no runner cache or authorization persistence.

## One command and library flow

With explicitly installed accepted equity-feature-files0.1.0a0, equity-feature-acquisition0.1.0a0 and equity-feature-example-extensions0.1.0a0, run:

```text
equity-feature-worker --acquisition-demo --approve-owned-fixture
```

This approval applies only to the generated owned synthetic local CSV. It performs selected LocalFileFactory acquisition, the existing pure trade calculation, an independent in-memory example sink and verified readback. It is not durable storage/provider acceptance. Without --approve-owned-fixture, execution is rejected before fixture creation or optional imports. The library equivalent is `run_owned_acquisition(approved=True)` from equity_feature_workers.acquisition_demo; it is a reproduction example, not a generic provider CLI. Production callers construct an explicit worker spec, registered factories/offer inventory/sink, call plan_acquisition, show the actual plan for user consent, then execute_plan. The existing caller wrapper can use run_session/run_required directly; adapters enforce their own controls in both routes.

Owned literal oracle was committed before runtime: times110/130/160, prices100/102/101 ticks(scale0USD), sizes2/3/5, known110/130/210, exact coverage3 in[100,200). Reconstruction C200/K210/E210 produces count3, volume10, notional1011, VWAP101.1 and mean10/3. Causal K150 retains the source population/future knowledge and returns the accepted null trade results. Independent tests compare full direct/planned encoded result/task/content-receipt identities and adversarial consent/capability/metadata boundaries. Actual review/native/source/main delivery evidence belongs in the linked story; tests do not establish source truth, financial rights or provider integration.
