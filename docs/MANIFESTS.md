# Experimental worker manifests — 0.1.0a2

Canonical [EQ057 #65](https://github.com/atulsrivas1/equity-features/issues/65) owns these contracts. They add supplied identity/admission only: no job execution, durable claims, catalog, acquisition or publication command yet.

`InputManifest(role, acquisition_sha256, revision_id, state, binding, known_at_ns=None)` retains an existing canonical InputBinding, exact revision/acquisition identity and unknown availability. Missing requires no binding/known-at. Empty requires complete zero coverage; complete requires complete positive coverage; partial requires incomplete coverage. These are caller declarations, not source truth or row-level known-at certification. Canonical row knowledge still governs calculations.

`TaskManifest` binds job/generation/partition/family, ordered instrument IDs, a canonical ConfigSpec, expected ordered FeatureHeaders, InputManifests, supplied governed IntervalSpecs, destination and ownership. One task targets one governed session with compatible features; history sessions are explicit context. A range job consists of ordered dependent session tasks where needed. Input/config/window/units/cutoff identities are preserved. Governed sessions must exactly match the canonical window order, with supplied nonoverlapping chronological bounds and matching target open/close. Positive batch/byte limits describe input admission quotas, not an RSS guarantee. Subsequent execution stories enforce actual budgets.

History tasks require `ordered_history=True` with ordered prior `warmup_sessions` or an initialization SHA256. This records required context; it does not certify that the correct window/state has been supplied. The calculation admission gates still apply. `merge_policy='none'` is the sole supported value: mathematical splitting/continuous-quote merging is unqualified; independent instrument tasks remain supported. Ownership is `serialized_destination` or `independent_destination`; distinct Parquet partitions in one root serialize, and DuckDB output retains one writer per database. Manifest validation does not acquire destination ownership.

`encode_task`/`decode_task` use the fixed input/config closure, ASCII sorted JSON, no whitespace/BOM/newline, exact Unicode escapes, no executable imports and tagged decimal int64. ConfigSpec is embedded as its exact accepted canonical JSON string; its digest algorithm remains unchanged. Worker field sets are closed and missing/extra/duplicate fields or noncanonical spellings reject. Version admission: efworker-task1, canonical0.0.4a4/schema1/mathv1. Manifest byte ceiling is 1MiB. Individual strings and sequences are limited to4096 characters/elements. A static configuration preflight rejects nested unsafe strings and oversized integers and uses a conservative encoded-size budget before the existing ConfigSpec serializer; valid-but-larger configurations are explicitly unqualified. All scalar integer fields reject bool and overflow. Errors use fixed ManifestErrorCode messages without caller text.

Task SHA256 hashes `efworker-task1` + NUL + exact encoded task bytes. ClaimIdentity separately binds task hash, owner/attempt and exact int64 supplied issue/expiry times; expiry must follow issue. Changing an attempt does not alter task identity or prove commitment. The reusable-input scope SHA hashes `efworker-reuse1` + NUL + the encoded config/inputs/instruments/governed sessions/warm-up/initialization tuple. Operational destination/job/generation identity is excluded from that scope; revisions, cutoff/configuration and initialization are included. No actual cache is supplied.

`OutputManifest(task, envelope, receipt=None)` reuses the accepted PublicationEnvelope and CompletionReceipt. It validates job/generation/partition/destination/versions and complete ordered descriptors against task config/timing/input/feature identity. Receipt admission calls the SDK's `verify_receipt` for key/identity/content/count matching. `committed` means a structurally verified supplied completion receipt; backend lookup and full physical result readback remain required by publication coordination. A caller can supply synthetic receipts; this type authenticates neither caller nor storage. Descriptors do not contain entity arrays, so instrument-to-result admission requires actual results in the execution story, not inference from descriptor metadata.

Output serialization uses efworker-output1 and embeds the exact existing SDK envelope/receipt JSON strings plus task JSON. It never introduces another result schema or sink protocol. A zero-result publication is not a feature-task completion; complete zero-row FeatureResults retain their own metadata and remain distinct from missing acquisition.

Run `python tests/manifest_example.py` after installing the supported core/SDK/worker combination. Its supplied synthetic two-bar oracle checks 500 shares, 51200 scaled notional, 102.6 weighted price and unavailable prior-close gap. Development tests include a separately hand-specified frozen JSON/domain-hash vector. Installed native wheel/sdist reports and actual publication evidence are recorded in the [delivery record](EQ057_DELIVERY.md); source tests alone do not establish release.

No changes to numerical formulas, canonical input/result schemas, source availability or sink storage/concurrency. Claims/retry/resume/cancel are EQ063; commands EQ058/059, barriers EQ060, publication EQ061, bounded execution EQ062, catalog EQ064, diagnostics EQ065 and representative pilot/capacity EQ066. Synthetic conformance admits no private data or historical generation.
