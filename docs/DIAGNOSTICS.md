# Experimental diagnostics API — workers0.1.0a10

EQ065#73 links workerPR22 and canonicalPR333. Frozen pre-code plan/oracle precede runtime. Diagnostics are local observations. Numerical formulas, units, initialization, eligibility, cutoffs, source entitlement, Task/Output/Result/Receipt codecs, sink locking and mandatory dependencies are unchanged. No output is automatically published.

## Recorder and identities

`ProgressRecorder(max_tasks=64, max_spans=4096, max_bytes=4194304)` belongs to its creating Thread object. Exact positive int64 bounds reject bool; fewer than512 bytes cannot hold the reserved header. Each attempt reserves2048 terminal/header bytes plus256 bytes per possible span before work; the snapshot header reserves512 bytes. Unused reservations are retained. Read-only `reserved_bytes` returns the full retained conservative wire reservation, including previous attempts and the current group, under creating-owner admission. Configured ceilings do not promise every combination fits. Snapshots are immutable tuples of frozen typed records. `snapshot().encode()` produces closed sorted ASCII JSON in memory, without filesystem/network access or an unbounded log.

Public exports: DiagnosticStage, DiagnosticStatus, StageTiming, TaskDiagnostic, DiagnosticSnapshot, ProgressRecorder. StageTiming contains stage, nonnegative int64 elapsed_ns or None, and nonnegative int64 probes. `available` means elapsed_ns is present. None is unavailable measurement, not zero work. Work status/reason is separate from availability. Fixed known codes exclude exception text, reprs, paths, credentials and configuration payloads. Recognized public family labels are retained; other labels become custom plus family SHA256. Partition labels are always SHA256. Original TaskSHA binds sealed work. Attempt ordinals begin at1 and are counts, not timestamps.

`prepare_session(..., progress=recorder)` reserves one acquisition attempt and returns existing PreparedSession. `run_session(..., progress=recorder)` reserves four stages and one slot from full command intent through sealed actual TaskSHA. Intent includes request/config/features/revision/destination context. `run_registered(..., progress=recorder)` additionally hashes explicit factory IDs/configs into intent, reserves five stages and measures configured source/sink construction. Credentials never enter intent or reports. Unsealed failures retain intent with task_sha256=None. Explicit retries are separate attempts. Cancellation after computation and recovery of uncertain commit do not imply a monotone status ladder.

Default calls retain existing behavior/outcomes and clock-free paths. Optional progress rejects insufficient report capacity before callbacks. Stage slots and terminal/failure rows are reserved before operations. Invalid bool/negative/overflow/decreasing counters yield unavailable timings without replacing actual durable receipts or successful results. Actual work KeyboardInterrupt/SystemExit propagates and records INTERRUPTED, distinct from unavailable telemetry.

## Measurement boundaries

Integer elapsed=end-start uses same-host Python3.12 perf_counter_ns. Its origin is undefined; it includes sleep and is not UTC/market time. Supported native Windows/Linux system-wide counters permit parent submission-to-child start differences. Process queue delay includes startup, IPC and scheduling. Implementation and rounded-up resolution in nanoseconds come from get_clock_info. Each implementation, monotonic and resolution property is copied exactly once before validating the cached primitives. Admit exact known implementation str, exact monotonic bool and finite positive exact int/float resolution (bool excluded); malformed metadata becomes unavailable/None while independently admitted counters and actual work are preserved. Integer storage does not imply nanosecond physical resolution. See [Python time](https://docs.python.org/3.12/library/time.html#time.perf_counter_ns) and [executors](https://docs.python.org/3.12/library/concurrent.futures.html).

Acquisition includes existing source/sink admission, bounded delivery validation and input sealing in session execution; prepare-only acquisition has no sink admission. Factory construction is separate. Calculation encloses the existing worker callback; pure numerical packages have no clocks. Serialization encloses existing result/envelope validation/encoding without an extra encoding pass. Publication encloses SDK publication plus original receipt/logical readback, including backend conversion and locking. These are combined boundaries, not isolated native conversion/lock costs.

`BoundedSupervisor.run(..., progress=recorder)` reserves all prepared tasks before children. Each child measures queue delay, calculation and serialization; only immutable closed sidecars cross IPC. Per-task elapsed covers the containing supervisor invocation through coordinator completion. Child metrics are copied/validated before publication. Malformed/missing metrics become unavailable without replacing independently valid computed results. Actual sidecar bytes remain inside existing per-task transport and three-copy child/IPC/returned-parent reservations. The full retained recorder wire reservation, including prior attempts and the newly reserved group, is additionally counted in coordinator resident admission before calculation or pool creation. Logical serialized reservations do not enforce interpreter/decoded-object/native RSS.

Without a publisher, supervisor reserves three spans per task. With a publisher it reserves5+3*N per task for N admitted tasks, covering child metrics, one submission and every existing bounded pending-queue drain pass. Large combinations can require explicit larger recorder bounds before work. No scheduler/retry/backoff was added.

`SerialPublisher.submit(..., progress=recorder)` requires coordinator/recorder ownership for telemetry and measures existing validation/serialization plus one nonblocking queue mutex probe, retaining enqueue counter. Default producers retain existing thread semantics. `drain(..., progress=recorder)` reserves current pending tasks under the existing mutex and measures enqueue-to-processing when available and actual combined publication/readback. backend_probe with probes=1 occurs only when that actual backend/barrier call returns BUSY. Its duration overlaps publication and includes lookup/conversion. It is not isolated OS blocking lock-wait duration. Queue probe/backpressure is separate. Existing lookup faults normalized to READBACK_FAILED are not relabeled BUSY. Unobserved enqueue timing is None. Sink-lock implementations are unchanged.

`evaluate_readiness(..., progress=recorder)` records scoped ready/waiting tasks and combined dependency inspection. `GenerationStore.publish(..., progress=recorder)` records generation_complete or waiting after the authoritative operation. `CatalogStore.select(..., progress=recorder)` records catalog_accepted or waiting after existing live verification/selection; intent includes GenerationSpec identity and expected sequence. Each contributor binds the group identity. Group intervals overlap across contributors. Supervisor/catalog/publisher reentry fences remain set through telemetry hooks/finalization, including a supervisor-owned publisher scope before initial report clocks. Reentrant owner default submit/drain returns BUSY before consuming queued work. Foreign default producers retain existing mutex/backpressure behavior. An observed supervisor drain spends only its reserved task population; concurrently queued foreign tasks remain pending for an explicit caller drain. Recorder owner/active admission precedes even the zero-node readiness fast path and dependency callbacks.

Stage arrays are observations, not a sorted timestamp timeline. Concurrent/combined spans overlap; their sum is not elapsed wall time. Frozen diagnostic_oracle spans total173ns against136ns containing elapsed. These are test-clock illustrations, not performance measurements.

## Acceptance authority and faults

Computed output, verified sink commitment, immutable generation completion and accepted catalog selection are distinct. Reports cannot certify them. Actual SDK receipt/full result/evidence bindings and GenerationStore/CatalogStore verification remain authoritative. Unknown/staged/partial/corrupt readback cannot produce acceptance. Explicit committed recovery uses original receipts without another begin. Typed failures remain scoped so unrelated work progresses.

Synthetic tests cover arithmetic, quotas before work, owner/reentry before clocks, redaction, revision/config identity, partial/invalid source, custom factories, sequential/thread/spawn-process full-wire parity, result failure, interruption, malformed sidecars, transport/resident admission, partial-write cancellation, uncertain-commit/readback recovery, queue/backend probes, dependency isolation and both physical Parquet/DuckDB sink pipelines. Existing controlled parent-termination, lock release, corruption, CAS, old-reader and historical .2/-.2/0 suites remain mandatory. Both backend names refer to sinks using accepted source contracts; no Parquet source adapter is added.
